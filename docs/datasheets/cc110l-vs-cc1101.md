# CC110L versus CC1101

Compares the CC110L on the IB01 with the CC1101 that freedo targets, to decide how much of freedo's radio code carries over.

Sources in this folder: `cc110l.pdf` (TI SWRS109C, revised December 2016) and `cc1101.pdf` (TI SWRS061I), with text extracts `cc110l.txt` and `cc1101.txt`. Line numbers below refer to the extracts.

**Result: confirmed, the CC110L is a simpler CC1101.** Register addresses, strobes and GDO codes that freedo and stock use are the same. No code change is needed for LQI, because freedo only uses the `CRC_OK` bit (`freedo/firmware/cc1101_bridge/cc1101_bridge.ino:700`) and never reads the LQI register. Whether it all behaves identically on air is still untested.

## What the CC110L removes

| Feature | CC1101 | CC110L | Effect on this project |
| :--- | :--- | :--- | :--- |
| Data whitening | Yes | Not mentioned | None; the Tado link does not use it (`PKTCTRL0=0x05`) |
| FEC | Yes | `FEC_EN` not in the datasheet | None; stock `MDMCFG1=0x22` leaves the bit clear |
| Wake-on-radio, `SWOR`, `SWORRST`, WOR registers | Yes | Absent | None; the coordinator stays in RX |
| LQI status register | `0x33` | `0x33` is `CRC_REG` (`:3381`) | Do not add LQI reads |
| LQI in appended status | Byte 2, bits 6:0 | Bits 6:0 reserved, only bit 7 `CRC_OK` (`:1752-1757`) | **Use only `CRC_OK`** |
| `RCCTRL`, `VCO_VC_DAC`, `PTEST`, `AGCTEST` | Yes | Absent | None found in freedo's firmware |

Strobes listed for the CC110L: `SRES`, `SFSTXON`, `SXOFF`, `SCAL`, `SRX`, `STX`, `SIDLE`, `SPWD`, `SFRX`, `SFTX`, `SNOP` (`:3227-3260`). That covers every strobe freedo uses.

## What stays the same

- Status registers freedo reads: `FREQEST` (`:3380`), `RSSI` (`:3382`), `MARCSTATE` (`:3384`), `TXBYTES` (`:3389`), `RXBYTES` (`:3391`). Freedo's frequency autotune can therefore work on the CC110L.
- GDO codes `0x00`, `0x01`, `0x04`, `0x07`, `0x2F` have matching descriptions (`:2906-2964`).
- 64-byte RX and TX FIFOs (`:1173`), frequency offset compensation (`:1674-1695`), Manchester option, variable packet length.

## Stock versus freedo register choices

Stock values are from `Tado_Hardware_Teardown.wiki/CC110-Register-Configuration.md`, freedo's from `freedo/cc1101/cc1101.go:45-83`.

| Register | Stock IB01 | Freedo | Note |
| :--- | :--- | :--- | :--- |
| `IOCFG0` | `0x01` threshold or end of packet | `0x07` CRC-OK packet | Freedo timestamps frame end on this edge, needed for CSL timing **[I]**. Prefer freedo's scheme |
| `IOCFG2` | `0x04` RX overflow | `0x00` RX threshold | Both valid |
| `FIFOTHR` | `0x03` (RX 16, TX 49) | `0x47` (33/32, `ADC_RETENTION` on) | `ADC_RETENTION` matters when waking from SLEEP (`:3543-3549`). The bridge need not sleep **[I]** |
| `PKTLEN` | `0x80` | `0xFF` | Maximum length in variable mode (`:3607-3610`) |
| `FSCTRL1` | `0x18`, 609 kHz IF | `0x06`, 152 kHz IF, commented "Tado firmware value" | Conflict; **decision: use `0x06`** |
| `FSCTRL0` | `0x00` | Per-module trim | See `open-questions.md` #7 |

All other values match the stock capture.

## Timing

- RX to TX switch: `782/fxosc` (`:2545`), about 30 µs at 26 MHz.
- TX to RX switch: `782/fxosc + 0.25/fbaudrate` (`:2544`), about 35 µs at 26 MHz and 50 kBaud.
- The radio switch is small against the 0-1 ms ACK gap, so SPI loading and MCU scheduling set the limit **[I]**.
- `SCLK` limits: `:1324-1341`.

## To port from freedo

1. Check frames with the `CRC_OK` bit, as freedo does.
2. Keep the GDO threshold-plus-end-of-frame interrupts.
3. Keep `FREQEST`-based trim.
4. Use `FSCTRL1=0x06`.
